Help and glossary

STAVE borrows how software developers keep their history to keep your music’s history. These are the words you’ll meet, explained with musical examples.

Glossary

No terms match. Try “commit”, “branch” or “merge”.

Draft

The piece you’re still writing. STAVE saves it every time you change a note.

Like a rough take in the studio, not yet named.

Commit

A point you save on purpose, with a message. Only commits enter the history.

Like naming a mix: "demo 1", "client mix".

Branches

An experiment that runs alongside the main version without touching the original.

Like trying a bridge with different chords.

Merge

Combine what you changed on one branch into another, usually the main branch.

Like picking the bridge you like and placing it into the main song.

Conflict

When both branches edit the same note, STAVE doesn’t decide for you; it asks which version to keep, bar by bar.

Like two people changing the third note of the same phrase.

Restore

Go back to the contents of an older point by creating a new commit. The old history is not deleted.

Like recreating an old mix as your newest one.

Fork and Pull request

A fork copies someone else’s project so you can remix it. A pull request proposes your changes back to the original project.

Like copying a friend’s song to rework it, then sending your version back for them to see.

Velocity and Quantize

Velocity is how hard each note is played. Quantize snaps notes onto the grid’s beats.

Like adjusting how hard keys are hit and fixing notes that fall off the beat.
